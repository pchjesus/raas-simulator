# RAAS Simulator v7.1 — PC 탐구·학습·임상 UX 통합 설계/검증 기록

> 기준: `main` @ `e266099a029dbd77bb0d9e371f9bac47042746f1`. 개발 브랜치: `feat/v7.1-pc-learning-clinical-ux`.
> 상태: **Phase 1 구현 및 CI 검증 단계**. `main`·Pages 미배포, 사용자 최종 승인 이전. 뒤의 Phase 2·3은 아직 구현 완료로 간주하지 않음.

## 변경 목표와 비범위

기존 v7의 네이비·민트 디자인, 모핑, 인터랙티브 9단계, 6개 약물, 4개 모델값, 가로 스크롤 그래프, 16개 학습, CKD/HFrEF 원본 엔진 및 Lab 공개 규칙을 유지하며 화면 구성과 정보 위계를 재설계한다. 모델·문항·정답·임상 근거·약물/진행 상태 머신은 변경하지 않는다.

## Phase 1 — 구현된 PC 탐구 화면

- **기본 모드**: 경로/설명 패널을 내용 높이에 맞춰 위쪽 정렬해 아래 빈 공간을 제거. 경로와 설명을 인접 배치하며 아래의 원본 약물·모델값/그래프 카드 유지. 그래프 1000×290 원본 가로 탐색 유지.
- **간편 모드, 화면 너비 >1160px**: 왼쪽 경로 아래에 실제 모델값 카드, 오른쪽 현재 단계 설명·진행 버튼 아래에 약물 적용/제거 카드. 경로–출력, 조작–약물 사이 시선 이동 최소화.
- **좁은 화면/모바일**: 기존 경로 → 설명/진행 → 약물 → 모델값 단일 컬럼 배치를 보존. 화면이 1160px 경계를 가로질러 변하면 기존 원본 노드를 재배치.
- 전환은 **동일한 `drugCard`, `outputCard` DOM 노드를 옮기는 방식**으로 처리. 중복 계산·중복 상태/이벤트 없음. `startViewTransition`, 빠른 모드 전환 보호 및 reduced-motion 유지.
- 배포 시 사용자 검토 대상: 1440×900에서 경로·수치·약물 조작이 의미 있는 스크롤 없이 확인되는지, 압축/줄바꿈과 각 패널 밀도는 적절한지.

## 위험 및 검증 게이트

| 위험 | 보존/검증 방법 |
|---|---|
| 노드 이동 중 입력 핸들러·현재 모델값 손실 | 기존 노드 재사용, 모드 전후 v6 snapshot 수치 동일성·약물 적용/제거 검증 |
| 간편/기본·브레이크포인트 연속 전환 | DOM 부모, 동일 요소 1개, 1160px 왕복 리사이즈 검사 |
| PC 개선의 모바일 회귀 | 390/1024/1440 Chromium 및 기존 v7 mobile 테스트 |
| 생리 모델·그래프·임상 공개 규칙 회귀 | 동결 v6 백업 기반 19개 역사적 스위트, v7 실제 루트 브라우저 검사 유지 |
| 키보드·접근성·Safari·실기기 | CI와 구분, 수동 검수 전에는 PASS로 기록하지 않음 |

검증자료: `tests/browser-v7.cjs`의 새 레이아웃/리사이즈/상태 단언, Actions `artifacts/v7.1/*.png` (기본·간편 1440×900 스크린샷). 이 문서 등록이나 코드 커밋 자체는 테스트 통과 근거가 아님.

## Phase 2 — 이후 진행 대상

학습 화면 우선순위를 질문 → 핵심 기전(밝은 민트 계열) → 의학적 의미·간호 사정·확인 근거(항상 노출) → 관련 단계 → 낮은 강조의 확인/성찰 활동 순으로 재배치한다. 원본 5단원·16항목 및 ACEi 실습 공개 규칙은 불변.

## Phase 3 — 이후 진행 대상

v7 고유 임상 워크스페이스: 환자 정보 → 임상 판단 → 간호 행동 → 결과/Lab·복습. 기존 `backups/v6.0-content-ia.html`의 상태·판정·정답·Lab 공개 로직만을 권위 있는 원본으로 사용하는 어댑터. 원본 v6 표시 UI를 장식하는 수준으로 종료하지 않는다.
