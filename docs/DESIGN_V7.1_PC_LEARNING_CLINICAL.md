# RAAS Simulator v7.1 — PC 탐구·학습·임상 UX 통합 설계/검증 기록

> 기준: `main` @ `e266099a029dbd77bb0d9e371f9bac47042746f1`. 개발 브랜치: `feat/v7.1-pc-learning-clinical-ux`.
> 상태: **Phase 1–3 코드 구현, 통합 QA 및 사용자 검토 대기**. `main`·Pages 미배포, 사용자 최종 승인 이전. 현재 커밋의 통합 CI PASS 전에는 완료로 확정하지 않음.

## 변경 목표와 비범위

기존 v7의 네이비·민트 디자인, 모핑, 인터랙티브 9단계, 6개 약물, 4개 모델값, 가로 스크롤 그래프, 16개 학습, CKD/HFrEF 원본 엔진 및 Lab 공개 규칙을 유지하며 화면 구성과 정보 위계를 재설계한다. 모델·문항·정답·임상 근거·약물/진행 상태 머신은 변경하지 않는다.

## Phase 1 — 구현된 PC 탐구 화면

- **기본 모드**: 경로/설명 패널을 내용 높이에 맞춰 위쪽 정렬해 아래 빈 공간을 제거. 경로와 설명을 인접 배치하며 아래의 원본 약물·모델값/그래프 카드 유지. 그래프 1000×290 원본 가로 탐색 유지.
- **간편 모드, 화면 너비 >1160px**: 왼쪽 경로 아래에 실제 모델값 카드, 오른쪽 현재 단계 설명·진행 버튼 아래에 약물 적용/제거 카드. 경로–출력, 조작–약물 사이 시선 이동 최소화.
- **좁은 화면/모바일**: 기존 경로 → 설명/진행 → 약물 → 모델값 단일 컬럼 배치를 보존. 화면이 1160px 경계를 가로질러 변하면 기존 원본 노드를 재배치.
- 전환은 **동일한 `drugCard`, `outputCard` DOM 노드를 옮기는 방식**으로 처리. 중복 계산·중복 상태/이벤트 없음. `startViewTransition`, 빠른 모드 전환 보호 및 reduced-motion 유지.
- 배포 시 사용자 검토 대상: 1440×900에서 경로·수치·약물 조작이 의미 있는 스크롤 없이 확인되는지, 압축/줄바꿈과 각 패널 밀도는 적절한지.

## Phase 2 — 구현 내용

- 학습 핵심 기전 카드를 기존 네이비에서 **읽기용 밝은 민트/청록**으로 변경했다.
- 원본 `lessonMedical`·`lessonNursing`·`lessonEvidence` 내용을 숨기던 `details`를 제거하고 **항상 표시되는 근거 패널**로 변경했다.
- 확인 활동과 성찰 카드는 오른쪽의 내용 높이에 맞춰 표시하며, PC의 본문을 더 넓혔다. 모바일은 세로 순서.
- 원본 v6 학습 데이터와 16개 항목, ACEi 예상→확정→관찰 게이트는 수정하지 않았다.
- `tests/browser-v7.cjs`에서 16개 핵심 기전/근거/의학/간호 내용의 원본 일치, 항상 표시, ACEi 조건을 검사한다.

## Phase 3 — 구현 내용 및 소스 계약

**보이는 임상 화면은 새 `#v71ClinicalWorkspace`로 교체**했다. 기존 iframe 임상 화면을 CSS로 꾸민 것이 아니다. CKD/HFrEF 사례 선택 뒤에는 환자 상황·현재 임상 판단/간호 행동·단계별 피드백·후속 Lab·문항별 복습을 v7 전용 HTML/레이아웃에서 표시한다.

- iframe의 동결 `backups/v6.0-content-ia.html`은 **별도 로드된 단일 권위 있는 임상 엔진**으로 유지. v7 브리지의 `clinicalView()`는 읽기 전용으로 원본 화면의 공개 상태/세션을 투영한다.
- `clinicalCommand()`는 원본 문항/간호 행동/다음/재시작/목록 버튼의 기존 이벤트 핸들러를 호출한다. 정답 판정·Lab 게이트·증례 내용은 복제하거나 수정하지 않는다.
- 새로운 선택지 제출 버튼은 **선택/제출 구분용 임시 UI 상태**만 가진다. 제출 시에만 원본 핸들러를 실행하고, v6의 공개 조건이 충족되기 전에는 정답·선택 해설·Lab이 투영되지 않는다.
- 완료 상태일 때만 원본의 동적 오답 우선 복습·교육 포인트를 노출. 근거는 기존 문구를 복사하여 읽기용 카드로 구성.
- 학습 탭 등으로 왕복하면 실제 임상 session을 보존. 다른 사례·다시 풀기는 별도 확인 후 원본 reset 동작을 따른다.
- ACEi 실습은 기존 검증된 iframe 조작을 계속 사용한다.

`tests/browser-v7.cjs`에 다음 흐름을 추가했다: 두 사례 모든 임상 판단(3+2)/간호 행동(3+2) 제출, 답안 선택/제출 구분, 피드백·Lab 실제 공개 게이트 일치, 탭 이동·복귀, 사례 초기화·결과·원본 동기화, PC 스크린샷. 실제 테스트 결과는 해당 GitHub Actions 커밋과 연결해서 확인해야 한다.

## 남은 QA 및 사용자 검토

- 전체 v7 Chromium 통합 + 모바일 + 동결 역사적 Node 스위트, FAST/FOCUSED/FULL 범위에 맞춘 테스트
- 개발 브랜치 최신 SHA에서 생성된 PC 기본/간편·학습·임상 스크린샷의 정보 밀도/시선 이동 검토
- 원본 Lab 조건의 전문가 사정, 실제 Safari·실기기·스크린리더·키보드·200% 확대 수동 테스트는 별도 게이트
- 현 코드가 시각적으로 승인되어도 명시적 사용자 요청 전 `main` 병합/Pages 배포 금지

### 구현 유의

`clinicalView()`는 현재 원본 임상 UI의 `hidden` 상태를 사용하므로, 향후 원본 v6 UI/게이트 코드를 수정한다면 읽기 전용 투영 계약도 통합 테스트로 확인해야 한다. 동결 v6 백업은 이번 작업에서 수정하지 않는다.
